# T4.2 — AssetPipeline (atlas, manifesto, hash estável)

Data: 2026-11-10. Worker claude2. Referências: PLANO T4.2, SDD-09 RF-09.2/RF-09.3, CA-09.1, CA-09.2, T-09.1..T-09.3; SDD-22 RF-22.9; D-03 (bloqueia T4.1).

## O que foi feito
- `tools/SideWar.AssetPipeline` (console net10.0 + SkiaSharp; lógica pública para os testes):
  - `SpritesFile`: parser de `sprites.json` (exatamente um de worldWidth/worldHeight, ids únicos).
  - `Rgba`: decodifica/codifica PNG RGBA **não premultiplicado**, `ZeroLowAlpha(8)`, bbox de alfa ≥ 8, crop, resize Mitchell (premultiplicado no resample).
  - `ShelfPacker`: shelf por altura decrescente (desempate largura, id), padding 2, máx. 1024×1024 (falha acima).
  - `AtlasBuilder`: trim só com `trim ≠ false`; zera alfa < 8 antes e depois do resize; mestre = `min(nativo, ceil(dip×masterScale))`, nunca amplia (masterScale 3,25 provisório); gera `atlas.png` + `atlas.json` (`inputsHash`, `pixelsHash`, sprites ordenados por id, `placeholder` quando aplicável).
  - `PipelineRunner`: lê `--in`, ignora PNG ausente só se `placeholder: true`, **não regrava** se `inputsHash` igual.
  - `ManifestVerifier`: se existir `assets/source/design/MANIFEST.json`, confere existência e sha256 (raiz array ou `{ "entries": [...] }`; itens `placeholder` pulados).
- `assets/source/sprites.json`: lista de RF-09.2 verbatim (14 ids). Nenhum PNG real criado.
- Testes: `tests/SideWar.Rendering.Tests/AssetPipelineTests.cs` (18 casos no total do projeto), PNGs sintéticos gerados em memória.

## Medido
- CA-09.1 (Linux): dois builds → `atlas.png`, `atlas.json`, inputsHash e pixelsHash idênticos; independente da ordem de entrada.
- CA-09.2: nenhum pixel do atlas com 0 < alfa < 8 (fixture com alfas 1..7); RGB zerado onde alfa=0; cor não premultiplicada preservada (±2).
- Trim opcional, mestre sem ampliação (24→24; 100→98; eixo de altura 70→59), shelf disjunto com padding (4 sementes × 60 retângulos), falha > 1024, runner (gravou / pulou sem tocar o arquivo / regravou ao mudar), manifesto (ok, hash errado, ausente).

## Decisões
- Lógica no próprio tool (RF-09.3); o projeto de testes de Rendering referencia o tool (não o contrário), sem mudar `Rendering`.
- `inputsHash` = SHA-256 de uma descrição canônica (schema, masterScale, por sprite: id, file, tamanhos, pivô, trim, sha256 do PNG), não do texto de `sprites.json`.
- `atlas.json` inclui `pixelsHash` (extra ao exemplo da SDD) para comparar entre SOs sem depender do encoder PNG.
- Largura do atlas = largura usada (não fixa em 1024).
- Formato do MANIFEST.json não está fixado na SDD (raiz); verificador aceita array ou `entries`.

## NÃO medido
- Determinismo no Windows (CA-09.1 completo exige Linux **e** Windows; rodar `win.sh test.ps1`).
- Atlas real: sem PNGs (D-03); RNF-09.1 (≤ 600 KB), masterScale final (DP-22.7), T-09.4 (ids/tamanhos vs tabela SDD-22) e CA-09.6.
- `atlas.png`/`atlas.json` não foram gerados nem embutidos (`EmbeddedResource` ainda não adicionado, pois quebraria o build).
