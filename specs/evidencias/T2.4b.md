# T2.4b — Persistence.Tests no Windows

Data: 2026-11-10. Worker claude2. Corrige T2.4. Referências: SDD-14 RF-14.2/14.3/14.9.

## Causa
Só nos testes, não na produção. `FakeFileSystem` indexava arquivos por string exata; o código de produção usa `Path.Combine`, que no Windows gera `\` (`/data\settings.json`), enquanto os testes esperam `/data/settings.json`. Resultado: lookups/Contains falhavam (quarentena, .bak e poda não eram encontrados) e `EnumerateFiles` comparava `Path.GetDirectoryName` (que no Windows devolve `\data`) com `/data`. No Linux `Path.Combine` usa `/`, por isso passava. Nomes de quarentena não têm `:` (carimbo `yyyyMMddHHmmss`), então a produção está correta.

## O que foi feito
- `tests/SideWar.Persistence.Tests/FakeFileSystem.cs`: novo `FakeFiles` (indexa por caminho normalizado `\`→`/`, expõe indexer/ContainsKey/Remove/Keys); `Calls`/`Fault` recebem caminho normalizado; `EnumerateFiles` compara diretório normalizado sem `Path.GetDirectoryName`. Nenhuma asserção foi alterada ou enfraquecida.
