# T5.8 — Menus nativos e bandeja completa

Data: 2026-11-10. Worker claude2. Referências: PLANO T5.8, SDD-15 RF-15.7/RF-15.8 (ajustados por ADR-028/031), CA-15.5, CA-15.6, SDD-23 CA-23.11 (gatilho), T1.12.

## O que foi feito
- `Menus/MenuModel.cs`: `MenuCommandKind`/`MenuCommand` (`OpensWindow` = Configurações/Sobre), `MenuState` (interativo, pausado, oculto, monitores, selecionado), `MenuEntry` e `MenuModel.Build` (puro): Modo interativo (✓), Pausar/Retomar, Ocultar/Mostrar overlay, Monitor ▸ (✓ no atual; cinza sem monitores), Configurações…, Sobre o SideWar…, Sair. Oculto: só "Mostrar overlay", Configurações, Sobre e Sair agem (RF-15.6).
- `Menus/NativeMenu.cs`: `NativeMenu.Show(owner,x,y,state)` = `GetForegroundWindow` → `SetForegroundWindow(owner)` → `TrackPopupMenuEx(TPM_RETURNCMD|TPM_RIGHTBUTTON|TPM_NONOTIFY)` → `PostMessage(WM_NULL)` → `DestroyMenu`; devolve `MenuResult(Command?, PreviousForeground)`; restaura o foco (`ForegroundRestorer`) salvo se o comando abre janela WPF (essa janela restaura `PreviousForeground` ao fechar). `ForegroundRestorer.Capture/Restore` públicos para o App/widget.
- `Tray/TrayIcon.cs`: clique direito → `MenuRequested` e, se `MenuStateProvider` definido, abre o menu no cursor e dispara `CommandSelected(MenuCommand, previousForeground)`; `ShowMenu(state,x,y)` público (o widget de SDD-23 pode reusar); `IsMenuOpen` (sem reentrância); ícone `.ico` embutido (`Tray/Resources/tray.ico`, 16/20/24/32/48, via `CreateIconFromResourceEx`, fallback no ícone stock; destruído no Dispose); `UsesEmbeddedIcon`.
- `scripts/gen-tray-ico.py`: gera o `.ico` PLACEHOLDER (arte real não existe no repositório; troque o arquivo).
- `csproj` (EmbeddedResource) e `NativeMethods.txt` (só acréscimos). Ações inexistentes (pausa, visibilidade, monitor, Configurações, Sobre, Sair) saem como evento; quem executa é o App/host.
- Testes: `MenuTrayTests.cs` (4 puros + 5 Windows).
